# Development Tasks

> **2026-09-23 题材变更**：本项目从「俯视 2D 小镇生活模拟」改为《离散星海》世界观下的
> 科幻游戏——远望级深空殖民舰「远望号」，玩家是底层船员。
> 小镇版本完整保存在 `town-life-sim` 分支，不再维护。
> **世界观唯一事实来源是 `docs/设定集.md`。**

## 已确认的设计决策

| 项 | 选择 |
|---|---|
| 玩法 | 保留 2D 俯视，沿用小镇版验证过的引擎 |
| 美术 | 一律先占位色块，每个素材在 manifest 里带中英文字描述；之后统一替换 |
| 尺度 | **1 格 = 一个人高 = 1.8 米**，所有尺寸由人物推出（`docs/尺度.md`，TASK-S5） |
| 舰桥规模 | **单层**（不做双层战时指挥中心），用相机跟随表现"比舰长室大得多" |
| 舰桥气质 | **反华丽**：固定弧形屏、实体按钮、机械开关、纸张，不做悬浮全息投影 |
| 舰长姓名 | **未定**，所有文本只用「舰长」称谓；命名由用户决定 |
| 场景结构 | **全船一张地图**，舱室之间是走过去，不做场景切换、不做黑屏加载（见 TASK-S3） |

### TASK-S2：舰桥
状态：已完成

- 40×20 格的舱段；指挥区 30×11 格（尺度见 TASK-S5：现为 54×20 m，可走地面 855 m²，
  文档写的 35×25 m / 约 700 m² 是设计意图，偏差记在 `docs/尺度.md`），
  四角切掉形成椭圆轮廓，外圈一圈舱壁
- 前方**整排弧面显示系统**；舰长指挥席居中（略高、不是王座）；六个部门席位齐全：
  导航、通信、动力、防务、科学、人员
- **反华丽落到实处**：机械应急开关面板（设定集原文"不完全依赖华丽的交互界面"）、
  纸质值班记录（"舰长桌上那张表就是从这里抄的"）、星图工作台明确写着
  "不是悬浮全息投影。整艘船上，能用手碰到的东西比能看见的更多"
- 前方**没有**甲板圈：舰桥之前是舰首深空防护结构。这一圈甲板曾经存在，
  但玩家永远走不到（上舰桥的路在艉部），看得见摸不着等于穿帮

**过程中踩的坑（记下来避免重犯）**：

1. **手调椭圆参数三次都不对。** 严格椭圆会把最上和最下两行整个排除，
   结果前方显示屏跑到船体外面。最后改成**三层显式定义**——
   `isHall`（切角矩形）/ 舱壁圈 / 外侧甲板——由构造保证正确，不再靠调参。
2. **先铺细节再做密封，细节会自己"长出"舱壁**，显示屏两端戳进船体。
   密封必须发生在铺细节**之前**。
3. **1×1 家具根本点不到。** 交互半径下限原来是 26px，但格子上可达点到
   家具中心的最近距离是 28.8px。下限改为 32px。这条影响了船上**所有**小物件，
   而且看起来完全正常。
4. 网格行数（20）是调过的：行数更多时，玩家抵达的艉部舱门下方会露出一大片
   裸结构，读起来像穿帮。

### TASK-S3：把舰长室和舰桥接成一张地图
状态：已完成

**用户要求**：两个场景之间要**无缝**——不要黑屏、不要加载，最好感觉像同一个场景。

- 结论：**只有一张地图才能真正做到无缝**。"两个场景都常驻、切换时瞬移"只是把接缝
  藏起来，接缝还在；而且相机、碰撞、可达性都会在边界处有特例。
- 甲板 40×40 格，自上而下：**舰桥（0~19 行）→ 通道（20~23 行）→
  舰长室（24~39 行）**。舰长室在舰桥**后面（艉侧）**、横向居中，这既是真实的船内布局
  （舰长室就在舰桥后面），也让两扇门能对上。
- **全船一个格大小**。原来舰桥用 48px 制造尺度感，现在改为靠"格子更多"——
  同一张地图上不可能有两种格大小，而且走过去时尺度不该变。
- 通道两侧是舱壁，两扇门**列号完全对齐**（`shipMap.ts` 在模块加载时断言，错开就启动报错）。
  宽度与门的做法后来在 TASK-S5 重定。
- 地图由**两个已验证的生成器拼出来**（`cabinGrid()` + `bridgeGrid()`），不是重画一遍。
  重画试过三轮，三次都把墙画到舰桥中间；拼接 + 只切一条直通道，代码更少也更对。
- 舱门方向改了：舰长室的门从**艉壁**挪到**前壁**（两侧设备面板跟着挪开），
  朝舰桥开。门的位置导出成 `CABIN_DOOR`，被门板盖住会直接报错。
- 舰长的位置唯一：他只在舰桥上。两个场景时代他在两边各出现一次，接成一张地图后
  那会明显荒谬。他的台词把两处串起来（"我的舱室就在走廊那头"），走过去才有意义。
- HUD 会报当前位置（`远望号 · 舰长室 / 通道 / 舰桥`）：没有过场可以交代"你到了哪儿"，
  就用文字交代。
- `config.ts` 里的 `BRIDGE_TILE`/`ROOM_COLUMNS`/`PLAYER_SPAWN` 等**删除**：
  尺寸归各自的 map 模块所有，`shipMap.ts` 是唯一决定谁在哪里的地方。
  同一份尺寸写两遍，就是两个事实来源的开始。

验收：
- ✅ 119 项测试全绿；`tsc` 严格 + `vite build` 通过
- ✅ **无缝是走出来的，不是说出来的**：测试按住「向前」420 帧，从舰长室一路走到舰桥，
  断言途中**每一帧位移不超过 2.6px**（150px/s ÷ 60fps = 2.5px）——
  藏在淡出后面的瞬移会在这里露馅；同时断言途经 `舰长室 → 通道 → 舰桥` 三段
- ✅ 用真实碰撞从出生点洪水填充：舱长室 311 格 + 舰桥 337 格**全部可达，无一遗漏**；
  任一可达格的四周都不是 `hull`
- ✅ 拼接保真：舰长室整块与 `cabinGrid()` **逐格相等**；舰桥除门口一圈外逐格相等；
  拼接只会把结构变成地板，绝不把地板变成结构
- ✅ 无头浏览器三帧截图（舱室 / 通道 / 舰桥）+ `#debug-probe`：
  `place` 依次为 舰长室 / 通道 / 舰桥，`artMissingCount = 0`、`artFailureCount = 0`

**新增的坑**：

5. **舰体结构里藏了一圈走不到的甲板。** 舰桥前方的"外侧甲板圈"从构造上算得出来、
   画得出来，但玩家唯一的上桥路径在艉部，所以那 30 格是**永远走不到的地板**——
   看得见、过不去。测试断言"每个可达格四邻都不是 hull"时才发现。
   教训：**可达性要用洪水填充去证，不能靠"看起来是地板"**。
6. **无头浏览器连续调用会互相卡死。** 同一条命令里跑第二次 Edge，
   或者上一轮的进程没退干净，后面的 `--dump-dom` / `--screenshot` 会静默返回空，
   甚至挂到超时（详见 `docs/TESTING.md`）。一次命令只跑一次截图，跑完清进程。

### TASK-S5：按人物身高重定全图尺度
状态：已完成

**用户反馈**：「美术素材还没加，试玩下来感觉地方有点窄了，尤其是走廊，以人物身高为 1.8m
为参考去设计地图吧」

- **把人物当作单位**：船员 1.8 m = 精灵 48 px；瓦片 48 px → **1 格 = 一个人高 = 1.8 米**。
  `TILE` 从 40 改成 48（= `TILE_SIZE`），于是美术**不再被缩放**：画多大就是多大。
- 病根找到了：原来是 **40 px/格 配 48 px 的人物**，人物比格子还高，每条走廊看起来
  都比它实际的格数窄一档。所以"窄"不是错觉，是尺度和画面对不上。
- **通道 3 格 → 4 格 = 7.2 m**（四个人并排；两人迎面不用侧身），屏幕上的宽度从
  120 px 涨到 192 px（+60%）。通道中央铺 2 格宽的导引灯带，两侧在两张地图之间的
  实心结构里加了一对设备舱——16 m 的空管子读起来比实际更长。
- **舱门 3 格 → 2 格 = 3.6 m**，两侧留出舱壁：门才读成"门"，而不是"走廊到头了"。
  舱门宽度小于通道宽度这件事由 `PASSAGE_WIDTH` 自动均分，宽度不够留门框时**启动报错**。
- 通道的列不再写死：由两扇门的位置加两侧等宽"肩"推导出来，门或原点漂移就是启动错误。
- 顺手修掉一个真 bug：拼接时会把通道范围内的**任何**非地板改成地板，门比通道窄之后
  这会在舰长室前壁上多开两个洞。现在舱室边界那一行不参与铺设，只认舱门。
- 新增 `tests/scale.test.ts`：人物与格的关系、通道/舱门比例、"两个人能并排通过"、
  "舱门不用对准就能进"、"通道是一段路不是一道门"、以及人物确实装得进一格。
  另修掉 `bridge.test.ts` 里一处**写死的 1.5 m/格**——尺度改了它却还绿着，正是这种
  陈旧数字会让偏差藏起来。
- 文档：`docs/尺度.md` 记录推导、各空间格/米/人高对照表，以及**与设定集绝对米数的偏差**
  （舰长室 120 m²、舰桥 700 m² 在一格一人高时分别只有 6×6 格和 19×14 格，比房间里的
  圆桌还小）。保留的是关系——舰桥仍是最大单间、走廊仍比普通走廊宽——不是数字。

验收：
- ✅ 9 个测试文件全绿（含新增 9 项尺度测试）；`tsc` 严格 + `vite build` 通过
- ✅ 洪水填充重新验证：两舱 + 通道全部可达，无一格走不到
- ✅ 无头浏览器截图：通道明显变宽，门有门框，美术仍 1:1（`artMissingCount = 0`）

**已知未完成**：家具尺寸还没按人物重定（圆桌 5.4 m、床 3.6×5.4 m 都偏大约 3 倍）。
房间现在够大，所以观感自洽；等正式美术进来时和出图一起定——是改小家具框，
还是让美术在框内画小。
